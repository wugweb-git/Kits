## 1. Architecture map (actual)
- WordPress core: theme.json defaults -> active theme theme.json -> (filter wp_theme_json_data_theme) -> user Global Styles (wp_global_styles post, per site).
- Theme: theme.json + styles/ variations + patterns/templates/parts + CSS (kit-tokens, kits, kit...) + inc/site-layer.php (the ONLY wp_theme_json_data_theme filter in the repo; merges assets/site/theme.json, absent from the distributed ZIP).
- Kits Core: independent plugin. Reads theme CSS for bundling (joined-css), guards fonts.php by get_template()==='kits-by-wugweb', updates theme via theme-updates.php (slug-hard-coded), admin shell, forms, presets (content types), brand customizer.
- Brand Customizer today: option kits_brand_tokens (per site) -> wp_head priority 100 inline <style>:root{--kit-*; --wp--preset--color--*} (and admin_head for the editor). It does NOT touch theme.json data.
- Tenants: not identified anywhere. "Tenant 1/2/3" are three hard-coded preset arrays in brand-customizer-model.php, chosen by a button. One WordPress install = one site = one option row.
