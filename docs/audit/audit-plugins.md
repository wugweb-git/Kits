# Wugweb six plugins: integration audit (read-only, from code)

Repo: /Users/abcom/Documents/GitHub/Kits/plugins. Paths below are relative to that folder. Date of audit 2026-11-25.
Method: grep + a script that lists every kits_*/KITS_* symbol and every cross-plugin function/constant, with a 3-line look-back for a guard; ambiguous cases were opened and read. "Guarded" = function_exists / defined / class_exists / early return in the same function. Claims about runtime behaviour are from reading code, not from running anything.

## Cross-cutting facts

* None of the six has a `Requires Plugins:` header, and only directoryweb (wugweb.com) and rankweb (animalwrites.in) have a `Plugin URI`. All have `Requires at least: 7.1`, `Requires PHP: 8.0`, and `Update URI: https://wugweb.com/plugins/<slug>/`.
* Kits Core sentinel: `define( 'KITS_CORE_LOADED', '1.0.0' )` at kits-core/kits-core.php:26 (double-load guard at :23).
* Each plugin defines a `*_STANDALONE` constant, but it is informational only. Nothing reads `DIRECTORYWEB_STANDALONE`, `PLANWEB_STANDALONE`, `MAILWEB_STANDALONE`, `SOURCEWEB_STANDALONE` or `INSIGHTWEB_STANDALONE` (only the define lines exist). Real behaviour comes from `function_exists( 'kits_*' )` and `defined( 'KITS_CORE_LOADED' )` at the call sites. RankWeb's `RANKWEB_STANDALONE` means "no Rank Math", not "no Kits Core".
* The pattern in the plugins that have a `standalone-fallback.php` (directoryweb, insightweb, mailweb, planweb): a `<plugin>_rest_can()` that delegates to `kits_shell_rest_can()` or falls back to a cookie-nonce plus capability check. directoryweb adds more wrappers (`directoryweb_icon`, `_date`, `_count`, `_simple_table`, `_ff_*`, `_private_dir`, `_scf_active`, ...). sourceweb and rankweb carry their own `*_rest_can()` instead of a fallback file.
* Every plugin registers its own top-level admin menu with or without Kits Core, in the "Wugweb block" at 58.x: SourceWeb 58.3 (sourceweb/includes/admin-menu.php:68), RankWeb 58.4 (rankweb/includes/overview.php:34), InsightWeb 58.5 (insightweb/includes/search-insights/admin.php:97), MailWeb 58.6 (mailweb/includes/overview.php:221), PlanWeb 58.7 (planweb/includes/admin.php:29), DirectoryWeb via `add_menu_page` at directoryweb/includes/directoryweb-ui.php:92. None registers under the Core `kits` menu except the legacy PlanWeb path (see planweb). Kits Core only lists them in its admin bar and tabs by reading their constants.
* The React admin screens (`build/index.js`) are mounted through Core's `kits_shell_app()` / `kits_shell_mount()` in all six. Without Core they show a notice (planweb, rankweb, mailweb) or a native WordPress fallback screen (directoryweb, insightweb, sourceweb).
* Theme coupling: no plugin checks `get_template()`, `wp_get_theme()` or the `kits-by-wugweb` slug, registers/uses theme block patterns, or reads theme.json. The only theme-ish coupling is front-end CSS class names `kit-btn`, `kit-card`, `kit-tag`, `kit-ico`, `kit-field`, `kit-minicard-list`, `kit-note`, `kit-faq-*` emitted by directoryweb (claim-page.php, listing-template.php, directory.php, directoryweb-local-card.php, directoryweb-find-help.php, directory-map.php, local-cards.php) and rankweb (faq.php, programmatic.php). The styles for those come from Core's `kits_use_component_style()` (guarded in all but one place, see directoryweb) or are absent. directoryweb ships its own CSS only for map/type icons. insightweb/includes/search-insights/server.php:215 lists `'kits-by-wugweb'` as a repo folder name for GitHub links (cosmetic).
* Animal Writes (aw_/AW_) coupling is widespread and is NOT provided by Kits Core or any of the six: functions such as `aw_hub_page`, `aw_hub_url`, `aw_hub_count_label`, `aw_hub_total`, `aw_hub_posts`, `aw_post_types`, `aw_press_list`, `aw_term_section`, `aw_filter_clauses`, `aw_item_date_ts`, `aw_item_more_card`, `aw_type_icon`, `aw_campaign_organiser`, `aw_core_simple_table`, `aw_social_on`, plus option/meta/CPT names (`aw_listing`, `aw_seo_settings`, `aw_si_*`, `aw_sources`). The CPT `aw_listing` is registered by directoryweb with its own plain fallback when `aw_content_type_args()` is missing (directoryweb/includes/bootstrap.php:17-35).

## Open points worth a decision

1. directoryweb claim review/native path calls `kits_ff_*`, `KITS_FF_SOCIAL`, `kits_simple_table`, and listing pages call `kits_date` without guards, so the "standalone" claim in its docs is false for those paths. Fix is mechanical (route through the existing `directoryweb_*` wrappers).
2. insightweb header comment and readme say Core and Rank Math are enforced; code does not enforce either. Choose one, then align docs or add the check.
3. sourceweb should either guard its InsightWeb keyword and DirectoryWeb calls or declare the dependency (Requires Plugins is not used by any plugin here, by design, because Core is loaded by Animal Writes Core on live).
4. rankweb's InsightWeb bridge hard-codes `WP_PLUGIN_DIR/insightweb/` and loads InsightWeb code while InsightWeb is inactive; its own comment says it is to be removed once InsightWeb is active on live.
5. `*_STANDALONE` constants are never read; they could be removed or actually used.
6. Many unguarded `aw_*` calls (rankweb hub/schema, directoryweb `aw_hub_page`, `aw_item_more_card`, `aw_type_icon`-style) depend on Animal Writes Core, which is not in this repo.
