## What changed since the 26 Nov report

- **Held code removed** (MailWeb retry queue, InsightWeb 404 and search logs). Stored data is deleted once on upgrade.
- **Animal Writes code is out of every plugin.** It lives in `sites/animalwrites/<plugin>/` (loaded as must-use plugins, not packaged in the plugin zips). A CI guard (`check-visible-brand.py`) fails if "Animal Writes", AWBI, NGO Darpan or the domain appears in a plugin string. The allow list is empty.
- **Neutral extension points:** `rankweb_post_type_roles`, `sourceweb_post_type_roles`, `insightweb_post_type_roles`, `sourceweb_starter_sources`, `planweb_import_source`, `directoryweb_meta_fields`, `directoryweb_claim_fields`, `directoryweb_ff_dates`, `mailweb_fcrm_blocked_emails`, `kits_error_page_marker`, `kits_features`, `kits_settings_fields`.
- **Kits Core 1.4.1:** hardening (form-key endpoint, atomic ALTCHA single use, preview token out of the query string, single-use settings download token, theme update package checked by SHA-256), `kits/socials` block, `kits/v1/site-check` route, 609 translatable strings.
- **Tests:** CI now runs every Kits Core test, the site-layer tests, the visible-brand guard, and the Playground smoke for all blueprints (generated by `tools/playground/build-blueprints.py`).

## Verified

- CI green on the released commits (b1f9266, 5bf809d). All 25 older cancelled CI runs were re-run one at a time: 25 of 25 green.
- Animal Writes site layer on a real WordPress (WordPress Playground with FluentCRM and Fluent Forms installed): 15 of 15 assertions pass and 50 admin screens load. This covers the layer's features, not Animal Writes content (listings, news, campaigns).
- Plugin Check on every plugin zip: the only remaining error is `plugin_updater_detected` / Update URI. It is deliberate for plugins distributed from GitHub and would block WordPress.org; the `-wporg.zip` build omits the header.
- Theme Check clean on the theme's wordpress.org build.
