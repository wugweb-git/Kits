# Product pages, registry and updates

One product, one version, one tag, one release. Nothing here combines products.

## Addresses

| What | Address |
|---|---|
| Index of products | https://wugweb-git.github.io/Kits/ |
| A product page (its `Plugin URI`) | https://wugweb-git.github.io/Kits/plugins/<slug>/ |
| The theme page | https://wugweb-git.github.io/Kits/themes/kits-by-wugweb/ |
| Registry (all current releases) | https://wugweb-git.github.io/Kits/registry/index.json |

The pages and the registry are generated by `tools/release/build-site.py` from the product files and the GitHub releases, and deployed by `.github/workflows/pages.yml` (on every push to `kits-suite`, and after each product release). Pages must be enabled once: Settings > Pages > Source: GitHub Actions.

## Releasing one product

1. Raise the version in the product: header `Version`, readme `Stable tag`, and add a changelog entry. `python3 tools/validate/check-versions.py` checks they agree (CI runs it).
2. Merge to `kits-suite` with green CI.
3. Run the "Release one product" workflow, choose the product. It refuses unless CI passed for that commit, builds that product's commercial and WordPress.org ZIPs, writes SHA256SUMS and a registry entry, creates tag `<slug>-v<version>`, verifies every asset downloads and matches, then refreshes the pages. A tag is never reused.

## Registry entry (schema_version 1)

`product, type, name, version, tag, requires_wp, requires_php, tested, license, page, source, source_commit, assets{name: {size_bytes, sha256}}`.

## Updates to sites (not built yet)

WordPress pulls updates. A site-side updater (Kits Core, `update_plugins_*` filter) would read the registry, compare versions, and offer the ZIP. Open decisions, owner's call: whether registry assets are public or per-site authenticated, which channel (stable/pre-release) each site follows, and the `Update URI` host. The WordPress.org build carries no `Update URI` and never updates itself from here.

## Plugin Check

`tools/validate/plugin-check.py` and `.github/workflows/plugin-check.yml` run the official Plugin Check (static checks) on every `wporg` build in WordPress Playground. Errors fail the job. Runtime checks need a full WordPress install and are not covered.
